# Целевая платформа и ресурсные ограничения

## Выданный каркас

На S4 в starter-проект добавляются Dockerfile, CI job, CMake-проект и CLI с
тестовым тензором. На S14 преподаватель выдаёт готовый C++ runner для ONNX
Runtime и ARM64 smoke-test. Студент изменяет два участка:

1. адаптер входного тензора и чтение имён входа/выхода своей модели;
2. измерительный участок: прогрев, число повторов и запись результата.

Загрузка ONNX Runtime, CMake boilerplate, multi-platform Docker и конфигурация
QEMU не набираются на семинаре и не оцениваются как знание синтаксиса.

## Обязательный маршрут без постоянного ARM64-стенда

1. Экспортировать зафиксированную модель в ONNX.
2. На S13 проверить одинаковые входы в PyTorch и ONNX Runtime Python.
3. На S14 подключить ONNX к выданному C++ runner и повторить проверку.
4. Готовый CI собирает и запускает Linux/ARM64-контейнер. Предпочтителен нативный
   `ubuntu-24.04-arm` runner; при его недоступности используется Docker Buildx с
   QEMU.
5. Время QEMU не публикуется как аппаратная задержка.
6. Измерить p50/p95 и RSS нативно на доступной x86_64-машине для обнаружения
   регрессий внутри проекта; результаты разных машин не ранжируют команды.

## Обязательные ограничения релиза

- размер `model.onnx` не более **20 MiB**;
- прирост пиковой RSS процесса C++ относительно запуска без модели не более
  **256 MiB**;
- FP32: максимальное абсолютное расхождение Python ↔ C++ не более $10^{-5}$;
- INT8: совпадение итоговых решений не ниже 99%, снижение основной метрики не
  более 0.02 абсолютного значения;
- ARM64 smoke test обрабатывает минимум 100 эталонных входов без ошибки и с тем
  же правилом решения.

## Переносной эталон Raspberry Pi 4B

На S15 преподаватель может принести один Raspberry Pi 4B и последовательно
прогнать все замороженные пакеты. Общая конфигурация: 64-bit Linux, CPU-only,
batch 1, четыре потока, 30 прогревочных и 1000 измеряемых вызовов.

Ориентир для малой сенсорной модели: **p95 ≤ 50 ms**. Результат попадает в
карточку модели как `rpi4-reference`. Если Pi недоступен, этот показатель
помечается `N/A` и не снижает оценку; обязательные ARM64 smoke test, размер,
память и численная эквивалентность сохраняются.

Raspberry Pi не подключается как постоянный self-hosted runner и не хранит
студенческие ключи. Пакеты переносятся локально, а таблица результатов
подписывается версиями ОС, ONNX Runtime и хешами моделей.
