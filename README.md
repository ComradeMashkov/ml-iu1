# Машинное обучение · ИУ-1 (САУ ЛА)

Материалы инженерного курса Машкова И. И. для шестого курса кафедры ИУ-1
МГТУ им. Н. Э. Баумана, осенний семестр 2026 года.

Курс посвящён моделям для сенсорных данных и их проверке перед переносом в
бортовое приложение. Технологический маршрут:

**scikit-learn → PyTorch → ONNX Runtime C++ → Docker → GitHub Actions**.

Первые занятия используют синтетические учебные наборы. Семестровый проект
выполняется на одном утверждённом реальном наборе. Для всех задач действует
общий протокол: формулируется эксплуатационный вопрос, фиксируются данные,
разбиение, базовая модель, метрики и вычислительные ограничения. Фотографии и
технический контекст взяты из открытых материалов NASA.

## Локальная проверка

Нужны [Quarto](https://quarto.org) и [uv](https://docs.astral.sh/uv/).

```bash
uv sync --locked
make verify
```

`make verify` проверяет lock-файлы, Python-код, тесты и полную сборку сайта.
При наличии локальных сценариев тесты также выполняют notebook с точными
вставками из текста преподавателя и сопоставляют отчёты с командным запуском.
Для просмотра:

```bash
make preview
```

## Учебная архитектура

Первый модуль выстроен как один сквозной цикл:

**L0: задача → признаки и цель → обучение → прогноз → ошибка** →
**S1: первый классификатор** →
**S2: сырой сигнал → проверенные признаки** →
**L1: честное разбиение и метрика** →
**S3: воспроизводимая базовая модель**.

На семинарах код пишет и объясняет преподаватель. Студенты следят за разбором
или повторяют действия в своём notebook. Все примеры, эксперименты и проверки
полностью разбираются на занятии; время на самостоятельные попытки не отводится.
Git-процесс, CI и готовый каркас будущего релиза вводятся в S4, когда уже
существует содержательный ML-конвейер.

Будущие занятия проектируются на этом фундаменте. L2–S6 вводят нейросеть и её
диагностику, L3–S7 — временные свёртки, L4–S10 — семейства задач, метрики,
эксплуатационный домен и стресс-тесты. В S8 фиксируется предварительный
интерфейс модели и начинается карточка модели; в L5–S12 добавляются гибридная
оценка, мониторинг, резерв и окончательный интерфейс. L6 объясняет численную
эквивалентность, квантизацию и измерительный протокол. S13 выполняет экспорт и
проверку в Python. На S14 готовые C++ runner и ARM64 smoke-test принимают
замороженную модель; меняются только адаптер входа/выхода и измерительный код.
S15 отведён индивидуальной демонстрации и, при наличии, эталонному запуску на
Raspberry Pi 4B.

## Редакционные правила

- Слайды обращены к аудитории от лица лектора. Распределение ролей
  «преподаватель делает…», «студент делает…» относится к подготовке занятия
  и остаётся за пределами публичных материалов. Сценарий содержит естественную
  устную речь; короткие служебные пометки оформляются отдельно.
- Риторические исправления и противопоставления вида «не X, а Y»,
  «это X, а не Y» запрещены на слайдах и в речи. Смысл формулируется прямо:
  «Метка хранит назначение осмотра». Повторяющиеся оговорки и общие фразы
  о важности материала удаляются при редактуре.
- В прозе используются русские термины; английское название даётся при первом
  появлении или когда оно совпадает с именем API.
- `train`, `validation`, `test`, `baseline` и `pipeline` допустимы в коде.
  В связном тексте предпочтительны «обучающая выборка», «валидационная выборка»,
  «тестовая выборка», «базовая модель» и «конвейер обработки».
- Число публикуется вместе с единицей анализа, версией данных, разбиением и
  командой воспроизведения.
- `score` — численная оценка модели. Для вероятностной модели указывается,
  вероятность какого события она оценивает. Соответствие этих оценок частотам
  событий проверяется отдельно; назначение осмотра не приравнивается к дефекту.
- В манифесте разбиения отдельно указываются единица решения, группа
  статистической зависимости, временная политика и объект эксплуатационного
  переноса. Одного поля `group_key` недостаточно.
- Учебная эвристика всегда подписывается как эвристика. Синтетические результаты
  обозначаются при представлении набора данных. Подпись источника фотографии
  или реального графика указывается рядом с изображением.
- Объём занятия определяется его результатами обучения и доступными 90 минутами.
  Для лекции ориентиром служат 24–32 основных учебных экрана; дополнительные
  примеры, доказательства и справочные материалы переносятся в приложение.
- В лекции оставляется время на разбор применения понятий и один полный
  численный пример обучения. Вопросы к аудитории и самостоятельные задания на слайдах
  и в сценариях лекций и семинаров не используются.
- Учебный слайд посвящается одному шагу объяснения. Определения вводятся
  последовательно, по одному или двум на слайде, рядом с соответствующим
  примером. Подробные пояснения сохраняются в сценарии; словарь всей темы
  распределяется по занятиям по мере применения терминов.
- Существенную часть объяснения несут крупные графики, фотографии оборудования,
  инженерные схемы и разобранные вычисления. Текст поясняет показанный объект.
  Изображение должно читаться с экрана аудитории; уменьшение рисунка ради
  дополнительного абзаца требует переработки слайда.
- Служебные перечни результатов обучения используются при подготовке курса.
  Слайды «Результат лекции» и формальный пересказ действий участников
  в конце лекции не добавляются. Финал завершает разобранную задачу.
- Новое базовое понятие проходит цепочку: инженерный смысл → точное определение
  → обозначения и формула → разобранный авиационный пример → применение в коде
  или отчёте. Эта цепочка разворачивается по ходу объяснения. В одном слайде
  размещается текущий шаг; определение предшествует применению термина.
- Для последовательности базовых определений используется курс
  [«Машинное обучение 1» НИУ ВШЭ, весна 2026](https://github.com/esokolov/ml-course-hse/tree/master/ml1-2026-spring/lecture-notes)
  без копирования примеров и структуры предметной области.
- Семинар состоит из 4–6 циклов «понятие и числовой пример → написание связного
  блока кода преподавателем → запуск → объяснение результата». Заранее готовятся
  импорты, генераторы, проверки форм и сохранение файлов. Выбор признаков,
  вычисления и сравнение результатов остаются видимыми в вводимом коде.
- Сценарий содержит точные вводимые блоки, ожидаемые результаты, объяснение форм
  массивов и физического смысла вычислений. Комментарии объясняют решение или
  обозначение; пояснять закрывающие скобки и хвалить краткость кода не требуется.
- График результата вычисляется из тех же данных и настроек, что и notebook.
  Отдельный условный рисунок явно подписывается как схема.
- Указанные объёмы служат ориентирами при подготовке. Проверка качества включает
  чтение речи вслух и просмотр каждого слайда в масштабе показа. Расписание
  должно вмещать объяснение терминов, живой кодинг и разбор вычислений.

## Как добавить занятие

1. Зафиксировать 2–3 наблюдаемых результата обучения.
2. Определить входные знания и итоговый файл, график или проверку.
3. Подготовить служебный код и выделить связные вычислительные блоки, которые
   преподаватель пишет и объясняет во время семинара.
4. Оставить время на запуск и разбор полученного результата.
5. Добавить материал в навигацию и выполнить `make verify`.
