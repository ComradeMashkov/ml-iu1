# Данные лекции 2

`delivery-orders-synthetic.csv` содержит 48 синтетических завершённых заказов.
Это учебная имитация, реальные журналы доставки мы не использовали.

Цель: полное время в минутах от принятия заказа до вручения. Момент прогноза:
принятие заказа. Отмены и незавершённые заказы в этой учебной задаче отсутствуют.

| Столбец | Значение |
|---|---|
| order_id | Уникальный идентификатор учебного заказа |
| split | train для D01-D36, test для D37-D48 |
| distance_km | Расстояние до ресторана, 0.5-6 км |
| kitchen_queue | Число заказов перед нашим в момент принятия, 0-8 |
| rain | Дождь в момент принятия: 0 или 1 |
| delivery_minutes | Завершённое время, в минутах |

В условии считаем, что сведения об очереди передаёт ресторан.
Фактические время готовности и маршрут курьера заранее неизвестны.

Генерация: NumPy default_rng, seed 20261005. Для каждой строки независимо
выбираем расстояние из 0.5, 1, ..., 6; очередь из 0, ..., 8; дождь из 0, 1;
целочисленный шум из -4, ..., 4. Время округляем до ближайшей целой минуты:

`12 + 4 * distance_km + 1.5 * kitchen_queue + 6 * rain + noise`.

Первые три строки заменены заранее заданными примерами для ручного счёта:
D01 (1 км, очередь 0, без дождя, 18 мин), D02 (2 км, очередь 4, без дождя,
27 мин), D03 (3 км, очередь 0, без дождя, 24 мин). Они также соответствуют
указанному механизму с допустимыми значениями шума. На них отдельно разбираем
один шаг градиентного спуска и минимум MSE. Это не вся выборка обучения.

До расчёта результатов зафиксированы разбиение, seed и три модели:
постоянное среднее train, линия по расстоянию, линейная модель по расстоянию,
очереди и дождю. Параметры всех вариантов оцениваем только по 36 train-строкам.
Метрики: MAE и RMSE. Test содержит 12 отдельных заказов. Seed не перебирали.

Рисунок с добавленным заказом 3 км и 90 мин представляет отдельный учебный
сценарий чувствительности к большому остатку. Строка не входит в этот CSV.
Рисунок цены поездки также является отдельной синтетической задачей:
12 расстояний от 0.5 до 6 км и цена `180 + 45*x + 6*x*x`, без шума.
Формула показывает изгиб и не описывает тарифы реального такси.

Синтетика удобна для прозрачных расчётов, но её метрики не оценивают качество
какого-либо сервиса. Нормальность ошибок не предполагаем как установленный
факт. Нормальная плотность в лекции объясняет одно из обоснований MSE.

## Те же данные на семинарах

S5 реализует среднее, MSE, две производные, один ручной шаг и обучение
на всех 36 train-заказах. S5 также сравнивает шаги обучения и измеряет MAE/RMSE на 12 отложенных заказах.
Разбиение сохраняется. S6 использует отдельные [данные поездок](TAXI-README.md)
и не требует выполнения S5.

|---|---:|---|

Долгий заказ не переносим в основной test. Для цены поездки отдельный test
не задан: показываем ошибку формы прямой и точное совпадение механизма
генерации с моделью по признакам x и x². Это не тариф реального сервиса.
