# Starter-проект S1–S3

Проект даёт работающий сквозной пример и готовую инфраструктуру. На S1–S3
короткие теоретические фрагменты чередуются с кодом в Jupyter notebook. CLI,
каталоги и JSON-сериализация подготовлены заранее.

## Первый запуск

Скопируйте папку `starter` в отдельный каталог без локальной `.venv`, затем:

```bash
uv sync --locked
make check
make first-model
```

Для семинара Jupyter запускается из того же каталога:

```bash
make notebook
```

`uv` создаёт зафиксированное Python-окружение и запускает установленный в нём
Jupyter. Код модели пишется в notebook; внутри ячеек команды `uv` не нужны.

Начальная проверка должна проходить. `make first-model` создаёт
`reports/s1-first-model.json` — учебный предварительный результат, а не итоговую
оценку качества.

## Самопроверка перед S1

До S1 нужны четыре действия: перейти в каталог, выполнить команду, открыть JSON
и объяснить форму массива. Проверка:

```bash
uv run python -c "import numpy as np; x=np.arange(6).reshape(3, 2); print(x.shape, x[:, 0])"
```

До S1 достаточно самостоятельно выполнить команду и объяснить значения `shape`
и `x[:, 0]`. Если результат непонятен, повторите пример с другим `reshape` и
условием выбора строк. Git до S4 не является входным требованием.

## Что подготовлено и что пишется на семинаре

| Семинар | Готово в starter | Код в notebook | Результат запуска |
|---|---|---|---|
| S1 | генератор, split-preview, CLI и отчёт | fit, score, один эксперимент и разбор ошибок | `reports/s1-first-model.json` |
| S2 | генератор, окна, orchestration и JSON | диагностика времени и интерполяция разрывов | `reports/s2-quality.json` |
| S3 | загрузка конфига, обучение и сериализация | агрегация score, порог и разбор FP/FN | `reports/runs/s3-baseline/` |

В `notebooks/` лежат короткие определения и пустые ячейки кода, соответствующие
последовательным частям семинара.

Чтобы вернуть все три notebook к этому начальному состоянию, выполните:

```bash
make reset-notebooks
```

Команда сохраняет Markdown и метаданные notebook, возвращает ровно одну пустую
code cell после каждого раздела и удаляет введённый код, лишние code cells,
номера запусков и результаты выполнения.

## Два учебных набора

- `sensor_source.py` создаёт отдельный синтетический IMU/GNSS-лог для S2;
- `course_case.py` создаёт синтетические оконные признаки привода для S1/S3.

Это не записи одного воздушного судна. Связь занятий — общий контракт обработки:
единицы, время, происхождение признаков, зависимые группы и воспроизводимый
отчёт. В S2 этот контракт сохраняется, а в S3 применяется к готовой таблице
признаков привода.

## Команды

```bash
make check        # lock, lint, format и тесты
make first-model  # рабочий классификатор S1
make sensor       # отчёт качества данных S2
make baseline     # baseline и validation-артефакты S3
make reset-notebooks  # очистить код и outputs во всех семинарских notebook
```

Команды `make sensor` и `make baseline` вызывают учебные функции S2/S3 после
переноса готовых реализаций из notebook в `src/ml_sau/`.
