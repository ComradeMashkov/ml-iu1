# Starter-проект S1–S3

Проект содержит учебные данные, служебный код и notebook для показа на семинаре.
Преподаватель объясняет понятие, пишет связный блок вычислений, запускает его и
разбирает результат. Студенты смотрят или повторяют код. Самостоятельных попыток
на занятии нет. CLI, импорты, проверки форм и запись файлов подготовлены заранее.

## Первый запуск

Скопируйте папку `starter` в отдельный каталог без локальной `.venv`, затем:

```bash
uv sync --locked
make check
make first-model
```

Для семинара Jupyter запускается из того же каталога:

```bash
make notebook
```

`uv` создаёт зафиксированное Python-окружение и запускает установленный в нём
Jupyter. Код модели пишется в notebook; внутри ячеек команды `uv` не нужны.

Начальная проверка должна проходить. `make first-model` создаёт
`reports/s1-first-model.json` — учебный предварительный результат, а не итоговую
оценку качества.

## Подготовка к S1

В первом разборе используются переход в каталог, запуск команды, чтение JSON
и форма массива. Пример для настройки окружения:

```bash
uv run python -c "import numpy as np; x=np.arange(6).reshape(3, 2); print(x.shape, x[:, 0])"
```

Вывод содержит форму `(3, 2)` и первый столбец `[0 2 4]`. На занятии этот же
принцип индексации применяется к таблице признаков. Git вводится в S4.

## Что подготовлено и что пишется на семинаре

| Семинар | Готово в starter | Код в notebook | Результат запуска |
|---|---|---|---|
| S1 | генератор, заданное разбиение, CLI и сохранение | выбор признаков, модель, обучение, решения по полётам, повторный эксперимент и разбор ошибки | `reports/s1-notebook.json` |
| S2 | генератор, проверки форм, опорная интерполяция и сохранение | диагностика, часы и единицы, маска разрывов, окна и матрица признаков | `reports/s2-quality.json` |
| S3 | загрузка конфига, обучение и сериализация | агрегация score, порог и разбор FP/FN | `reports/runs/s3-baseline/` |

В S1 notebook сохраняет результаты выполненных ячеек в `reports/s1-notebook.json`.
Команда `make first-model` отдельно вычисляет эталонный результат и сохраняет
`reports/s1-first-model.json`; содержимое двух отчётов должно совпадать.

S2 также сохраняет `reports/s2-features.csv` с признаками допустимых окон и
`reports/s2-windows.csv` с временем начала и признаком допустимости всех окон.
Так можно проследить, какие участки лога исключены из таблицы для модели.

В `notebooks/` лежат определения, подготовленный служебный код и места для
связных вычислительных блоков. Преподаватель вводит каждый блок целиком и
объясняет промежуточные значения. Ячейки выполняются сверху вниз. Первая ячейка
S1/S2 определяет корень проекта: пути к конфигурации и отчётам одинаковы при
запуске из `starter` и `starter/notebooks`.

Чтобы вернуть все три notebook к этому начальному состоянию, выполните:

```bash
make reset-notebooks
```

Команда возвращает исходный подготовленный код после каждого раздела и удаляет
дописанные строки, лишние code cells, номера запусков и результаты выполнения.

## Два учебных набора

- `sensor_source.py` создаёт отдельный синтетический IMU/GNSS-лог для S2;
- `course_case.py` создаёт синтетические оконные признаки привода для S1/S3.

Это не записи одного воздушного судна. Связь занятий — общий контракт обработки:
единицы, время, происхождение признаков, зависимые группы и воспроизводимый
отчёт. В S2 этот контракт сохраняется, а в S3 применяется к готовой таблице
признаков привода.

## Команды

```bash
make check        # lock, lint, format и тесты
make first-model  # рабочий классификатор S1
make sensor       # отчёт качества данных S2
make baseline     # baseline и validation-артефакты S3
make reset-notebooks  # восстановить заготовки и очистить outputs во всех notebook
```

Команды `make first-model` и `make sensor` вызывают полные эталонные реализации
S1/S2 из `src/ml_sau/`. На семинаре результат написанного notebook сверяется с
этими реализациями. Команда `make baseline` пока относится к заготовке S3 и
требует завершения её учебных функций.
