# Starter-проект S1–S3

Проект даёт работающий сквозной пример и готовую инфраструктуру. На каждом
семинаре студент принимает 2–4 содержательных решения; создание CLI, каталогов и
JSON-сериализация уже реализованы.

## Первый запуск

Скопируйте папку `starter` в отдельный каталог без локальной `.venv`, затем:

```bash
uv sync --locked
make check
make first-model
```

Начальная проверка должна проходить. `make first-model` создаёт
`reports/s1-first-model.json` — учебный предварительный результат, а не итоговую
оценку качества.

## Входная диагностика

До S1 студент должен уметь перейти в каталог, выполнить команду, открыть JSON и
объяснить форму массива. Проверка:

```bash
uv run python -c "import numpy as np; x=np.arange(6).reshape(3, 2); print(x.shape, x[:, 0])"
```

Все четыре пункта [входной диагностики](../prerequisites.qmd) должны получить
статус `passed` до S1. Если значения `shape` и `x[:, 0]` непонятны, пройдите
маршрут восстановления и повторную попытку с преподавателем. Git до S4 не
является входным требованием.

## Что подготовлено и что делает студент

| Семинар | Готово в starter | Самостоятельная работа | Артефакт |
|---|---|---|---|
| S1 | генератор, разбиение-preview, модель, CLI и отчёт | выбрать набор признаков, предсказать эффект, разобрать ошибки | `reports/s1-first-model.json` |
| S2 | генератор, окна, orchestration и JSON | проверить время, задать политику интерполяции, написать граничные тесты | `reports/s2-quality.json` |
| S3 | загрузка конфига, обучение, сохранение модели и отчётов | агрегировать score, выбрать порог, проверить манифест и ошибки | `reports/runs/s3-baseline/` |

S1–S3 выполняются индивидуально. Сосед может проверить объяснение или тест, но
каждый студент создаёт собственный артефакт и отвечает за решения.

## Два учебных набора

- `sensor_source.py` создаёт отдельный синтетический IMU/GNSS-лог для S2;
- `course_case.py` создаёт синтетические оконные признаки привода для S1/S3.

Это не записи одного воздушного судна. Связь занятий — общий контракт обработки:
единицы, время, происхождение признаков, зависимые группы и воспроизводимый
отчёт. В S2 студент сохраняет этот контракт, а в S3 проверяет его применимость к
готовой таблице признаков привода.

## Команды

```bash
make check        # lock, lint, format и тесты
make first-model  # рабочий классификатор S1
uv run python -m ml_sau.sensor
uv run python -m ml_sau.baseline --config configs/baseline.json
```

Две последние команды вызывают учебные функции S2/S3 и начинают работать после
их реализации.
