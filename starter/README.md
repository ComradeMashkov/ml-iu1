# Starter-проект S1–S4

Код и данные первых занятий. S1 начинает с одного признака и обучения
перебором четырёх порогов. S3 и S4 переходят к градиентному спуску
и проверке реальных сообщений.
S2 сохранён как дополнительный материал и не требуется для новых занятий.

## Запуск

Скопируйте папку `starter` целиком без локальной `.venv`, затем выполните
из этой папки:

```bash
uv sync --locked
make notebook
```

Jupyter откроет каталог `notebooks`. Выберите Python из созданной `.venv`.
В ячейках команды `uv` не нужны. Пакеты загружаются при установке окружения.
Сами новые занятия после установки работают без сети: набор SMS уже в `data/`.

| S4 · Проверка модели | [notebook](notebooks/S04-live-coding.ipynb) | [решение с выводом](notebooks/solutions/S04-complete.ipynb) | [s04.py](lessons/s04.py) |

Начальная версия содержит определения и подготовленные ячейки. Шесть
основных блоков появляются по ходу объяснения. Выполненная версия содержит
весь код и ожидаемые результаты. Для повторного опыта запускайте её сверху
вниз в новом ядре. Повтор ячейки с изменением параметров продолжает менять
текущее состояние, если параметры в ней не сбрасываются.

S3 использует четыре придуманных сообщения и обычные циклы Python.
После первого шага: `w=0.5`, `b=0`, средняя потеря `0.545475`.
После 200 шагов: `w≈4.417`, `b≈−6.357`, потеря `0.054416`.
График строится из того же списка `loss_history`.

S4 использует [UCI SMS Spam Collection](data/README.md). Код удаляет повторы,
делит 5159 сообщений на 3095 / 1032 / 1032, обучает один вес и выбирает
порог только по валидации. Блок 6 выполняется после фиксации порога.
Методика и ограничения описаны вместе с данными.

## Отдельный запуск

```bash
make s03          # учебный цикл и график
make s04          # опыт на реальном корпусе
make check        # lock, lint, format и тесты
```

При запуске S3 в среде без окон можно использовать
`MPLBACKEND=Agg uv run python lessons/s03.py`. Для показа графика в аудитории
удобнее notebook.

S1 использует обычные списки, условия и циклы. Для порогов 40, 50, 60, 70 °C
получаются 3, 3, 1, 3 ошибки. Выбранные 60 °C дают 4 совпадения из 6 на новых
примерах. Среднюю температуру и метку хранят в двух списках одного порядка.

S2 — дополнительный материал на 55 минут. Из 14 строк CSV остаются 10:
три отложены из-за значений, одна является точным повтором. Средние трёх
измерений дают обучающие данные S1. [Описание данных](data/INTRO-README.md).
S2 отдельно не проводится; необходимые операции для SMS разбираются в S4.

```bash
make s01         # перебор порогов и проверка
make s02         # подготовка reports/s2-temperature-features.csv
```

Команды `make first-model` и `make sensor` запускают те же новые примеры.
Прежние расширенные модули `ml_sau.first_model` и `ml_sau.sensor` сохранены
для отдельного изучения. В первые семинары их API и служебные отчёты не входят.
Git и история изменений вводятся при подготовке S5, CI — на S8.

## Сброс начальных версий

```bash
make reset-notebooks
```

Эта команда очищает все начальные notebook S1–S4, включая введённый в них
код и результаты. Перед сбросом сохраните свои выполненные копии отдельно.
Каталог `notebooks/solutions` команда не меняет.
